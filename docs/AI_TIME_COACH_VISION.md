## 核心定位

**从"时间追踪工具"升级为"AI 驱动的认知辅助助手"**

RecordTime 专门用来精准跟踪用户对桌面应用的真实使用时间，并根据大模型 + 时间管理知识库，提供更具可行性的任务建议规划，提供可持续的正向反馈。

### 核心理念

> **不是控制时间、管理时间，而是结合人脑的一般规律，顺应认知特点，提供可操作的建议。**

## 四层架构设计

### 第一层：精准跟踪（数据采集层）

**目标**：覆盖足够多的使用场景，制定对应的时间跟踪策略

#### 当前活动类型及检测优先级

| 优先级 | 类型 | 检测逻辑 | 状态 |
|--------|------|----------|------|
| 1 | Idle | 空闲 >5分钟无输入 | ✅ 已实现 |
| 2 | Video | MediaSession播放 / 视频应用+音频活动 / 浏览器视频 | ✅ 已实现 |
| 3 | Meeting | 会议应用进程 + 音频活动 | ✅ **新实现** |
| 4 | Gaming | 全屏+高频输入 / 游戏相关进程名 | ✅ 已实现 |
| 5 | ActiveTyping | >20键/30秒 或 >10键+>5点击/30秒 | ✅ 已实现 |
| 6 | Reading | 滚轮>10次/30秒 + 键盘<5次/30秒 | ✅ **新实现** |
| 7 | PassiveBrowsing | 窗口有焦点但未达到以上阈值 | ✅ 已实现 |

#### 🔴 发现的问题

| 问题 | 描述 | 影响 | 状态 |
|------|------|------|------|
| ~~会议检测未使用~~ | ~~`IsOnlineMeeting()` 方法存在但未在 `DetermineActivity()` 中调用~~ | ~~会议应用被归类为 PassiveBrowsing~~ | ✅ 已修复 |
| ~~**音乐检测未使用**~~ | ~~`IsMusicPlayer()` 方法存在但未在活动判定中使用~~ | ~~无法区分"听音乐工作"场景~~ | ✅ 已修复（通过后台音乐检测） |

| ~~**浏览器视频检测不精确**~~ | ~~`BrowserVideoPlaying = isBrowser && isMediaPlaying`~~ | ~~如果开着浏览器同时Spotify播放，会误判为浏览器视频~~ | ✅ 已修复 |

#### 缺失的使用场景

| 场景 | 特征 | 检测思路 | 状态 |
|------|------|----------|------|
| ~~**阅读/学习**~~ | ~~长时间看屏幕，偶尔滚动，极少键盘~~ | ~~新增滚动事件追踪 + 低键盘活动判定~~ | ✅ 已实现 |
| ~~**会议/通话**~~ | ~~使用会议软件 + 有音频活动~~ | ~~利用已有的 `IsOnlineMeeting()` + 音频检测~~ | ✅ 已实现 |
| ~~**深度工作**~~ | ~~长时间专注单一应用，持续输入~~ | ~~会话时长 + 无切换 + 持续活动~~ | ✅ 已实现（通过切换频率检测） |
| ~~**浅层操作**~~ | ~~频繁切换应用，碎片化操作~~ | ~~切换频率统计 + 短会话检测~~ | ✅ 已实现（通过切换频率检测） |
| ~~**边听边做**~~ | ~~音乐/播客 + 其他工作~~ | ~~后台音频检测 + 前台应用活动~~ | ✅ 已实现（SystemState.HasBackgroundMusic） |

#### 输入监控能力

| 维度 | 当前状态 | 备注 |
|------|----------|------|
| 键盘按键 | ✅ 30秒滑动窗口计数 | WH_KEYBOARD_LL hook |
| 鼠标点击 | ✅ 30秒滑动窗口计数 | WH_MOUSE_LL hook |
| 鼠标移动 | ✅ 30秒累计距离 | 忽略 <5px 微小移动 |
| 系统空闲 | ✅ GetLastInputInfo | Win32 API |
| 滚轮滚动 | ✅ 30秒滑动窗口计数 | WM_MOUSEWHEEL hook **新实现** |
| 应用切换 | ✅ 1/5/10分钟切换次数 | 队列追踪 **新实现** |
| 输入节奏 | ❌ 未实现 | 可用于区分"突发输入"vs"持续输入" |

### 第二层：知识库（认知原则层）

**目标**：建立时间管理的基础原则，结合人脑认知规律

#### 人脑一般规律（待整理）

- **专注周期**：因人而异，非固定 25 分钟
- **注意力曲线**：一天中的高峰与低谷时段
- **任务切换成本**：上下文切换的认知代价
- **休息恢复价值**：适时休息对效率的正向影响
- **心流状态条件**：进入深度专注的触发因素

#### 知识库形式（待定）

- [ ] 内置原则库（预定义的认知规律）
- [ ] 用户画像（个人行为模式学习）
- [ ] 目标设定（用户自定义的目标和偏好）

---

### 第三层：建议规划（AI 输出层）

**目标**：AI 结合知识库 + 用户具体数据，生成可操作建议

#### 输入

- 用户行为数据（应用使用时间、活动类型、切换频率）
- 知识库原则（认知规律、最佳实践）
- 用户目标/偏好

#### 输出

- 可操作的具体建议
- 时机恰当的提醒
- 个性化的任务规划

#### 技术方案（待定）

- [ ] 本地 LLM（隐私优先）
- [ ] 云端 API（能力更强）
- [ ] 混合方案（敏感数据本地，建议生成云端）

---

### 第四层：正向反馈（激励层）

**目标**：确定性与非确定性的有机结合

#### 确定性反馈

- 目标达成 → 明确奖励
- 进度可视化
- 成就系统
- 给用户掌控感和可预期性

#### 非确定性反馈

- 随机惊喜奖励
- 不可预期的鼓励
- 激发好奇心和持续参与
